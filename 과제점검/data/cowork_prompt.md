## 해야 할 일

다음 순서로 진행해줘.

### 1단계 — 과제 요구사항 파악
`hwXX.txt`를 읽고 각 문제의 정답 로직을 정리해줘.
이게 아래 로직 이슈 판단 기준이 돼.

### 2단계 — GitHub 판정 매핑
GitHub xlsx의 `종합` 열 값을 아래 이모지로 변환해줘.

| xlsx 종합 값 | 이모지 판정 |
|-------------|------------|
| 정상 | `🟢 이상 없음` |
| 폴더미정리 (이슈 없음) | `🟡 폴더 미정리` |
| 이슈있음 (1건) | `🟡 경고` |
| 이슈있음 (2건+) | `🔴 이슈 복수` |
| 실행오류 | `🟠 실행 오류` |
| 미제출 / 미등록 | `⛔ 미제출` |

### 3단계 — LMS 코드 분석
각 학생의 `.py` 파일을 읽고 아래 기준으로 판정해줘.

**LMS 판정 (D열)**
- `✅` : .py 있고 ast.parse 통과
- `❌`  : .py 없음 (온라인텍스트만, 미제출 등)
- `🔶` : .py 있으나 SyntaxError 또는 RuntimeError

**로직 이슈 (F열)** — 1단계에서 파악한 루브릭 기준으로
- 없으면: `-`
- 있으면: `파일명.py: 이슈 설명` 형식, 여러 개면 `;`으로 연결
- .py 자체가 없으면: `—`
- **[LMS]/[GitHub] 접두어 절대 사용 금지**, LMS+GitHub 이슈 통합 후 중복 제거

**코드 체크 (H열~)** — 아래 ✏️ 항목 기준으로 True/False

### 4단계 — data/hwXX.py 작성
분석 결과를 바탕으로 `과제점검/data/hw10.py`를 작성해줘.
`data/hw_template.py` 형식을 따르고, 학생 순서는 학번 오름차순.

## 판정 기준 요약 (고정 — 수정 불필요)

### 최종종합 (G열) 로직
```
LMS가 ✅/❌(파일 있음) AND GitHub ≠ ⛔  →  제출
LMS가 ✅           AND GitHub ≠ ⛔  →  제출     (위 포함)
그 외 (하나라도 없음)                →  일부제출
LMS가 — AND GitHub = ⛔             →  미제출
```

### input() 사용 파일 실행 시 timeout
자동 점검에서 `실행오류`로 표시되더라도 인터랙티브 프로그램이면
로직 이슈가 없는 한 GitHub 판정을 `🟢 이상 없음` 또는 `🟡 폴더 미정리`로 올려줘.
