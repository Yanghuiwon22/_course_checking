# 프로그래밍원리와실습 — 과제 점검 작업 가이드
목적: LMS에서 다운로드한 과제 ZIP 폴더를 열고, `과제XX_점검리포트.xlsx`와 `과제XX_최종버전_기준.txt`를 동일한 형식으로 매번 자동 생성하기 위한 절차서입니다.

> 프로젝트 전체 개요 및 스크립트 실행법은 상위 폴더의 [`CLAUDE.md`](../CLAUDE.md)를 참조한다.

## 1. 사전 준비

### 1-1. LMS에서 받는 폴더 구조
Moodle "모든 제출물 다운로드" 시 아래와 같은 구조로 압축됩니다.
```
과제XX (Homework XX)-XXXXX/
├── 학생이름_NNNN_assignsubmission_file/      ← 파일 제출
│   ├── (ZIP 파일 or .py 파일 직접 or 서브폴더)
├── 학생이름_NNNN_assignsubmission_onlinetext/ ← 온라인텍스트 제출
│   └── onlinetext.html
└── ...
```

### 1-2. 시작 전 할 일
1. **ZIP 압축 해제**: 폴더 내 모든 `.zip` 파일을 먼저 풀어준다.
   - 권한 오류 시 `/tmp_unzip/` 등 임시 경로에 풀고 복사
2. **GitHub 엑셀 확인**: `과제XX_점검리포트_github.xlsx`가 미리 제공된다. 이 파일의 `종합` 열 값을 이모지 판정으로 변환해 사용한다.

## 2. 리포트 파일 구조

### 2-1. 시트 구성 (3개)
| 시트명 | 내용 |
|--------|------|
| 종합현황 | 전체 학생 데이터 + 하단 요약 |
| 로직이슈상세 | 로직이슈가 실제로 있는 학생만 |
| 미제출 | 미제출 + 일부제출 학생 |

### 2-2. 열 구성

#### 기본 열 (A~G) — 매 과제 공통
| 열 | 헤더 | 설명 |
|----|------|------|
| A | 이름 | 학생 이름 |
| B | 학번 | 학번 |
| C | GitHub ID | GitHub 계정명 |
| D | LMS 제출 | ✅ / ❌ / — |
| E | GitHub 제출 | 이모지 판정 (6종, 아래 참조) |
| F | 로직 이슈 (LMS & GitHub) | 이슈 내용을 줄글로 서술 (`파일명: 설명; 파일명: 설명` 형식) |
| G | 최종종합 | 제출 / 일부제출 / 미제출 |

#### 코드 체크 열 (H열~) — 과제별로 항목 달라짐
F열 줄글의 이슈 중 **자주 반복되는 패턴**을 열 단위로 뽑아 ✅ / 빈칸으로 표시.
헤더 행 위에 **"코드 체크"** 병합 그룹 헤더를 올려 시각적으로 구분.

> ※ 체크 항목은 과제마다 채팅에서 함께 제공됩니다.

## 3. 판정 기준

### 3-1. LMS 제출 (D열)
| 값 | 조건 |
|----|------|
| `✅` | .py 파일이 있고 구문 오류 없이 실행 가능 |
| `❌` | .py 파일은 있으나 구문/런타임 오류 발생 |
| `—` | .py 파일 없음 (온라인 텍스트만 제출, txt/zip만 있음, 미제출 등) |

### 3-2. GitHub 제출 (E열) — 이모지 6종
GitHub 엑셀의 `종합` 열 값을 아래 이모지로 매핑합니다.

| 이모지 판정 | 매핑 기준 | 색상 (HEX) |
|------------|----------|-----------|
| `🟢 이상 없음` | 폴더 정상 + 코드 이상 없음 | `D4EDDA` (연두) |
| `🟡 폴더 미정리` | 폴더 구조 비정상 + 코드 이상 없음 | `FFF3CD` (연노랑) |
| `🟡 경고` | 코드 이슈 1건 (경미) | `FFF3CD` (연노랑) |
| `🟠 실행 오류` | 실행 시 예외 발생 (TypeError, NameError 등) | `FFE5CC` (연주황) |
| `🔴 이슈 복수` | 코드 이슈 2건 이상 | `F8D7DA` (연분홍) |
| `⛔ 미제출` | GitHub 파일 없음 또는 저장소 미등록 | `E2E3E5` (연회색) |

**매핑 규칙 상세:**
- GitHub xlsx `종합` = `정상` → `🟢 이상 없음`
- GitHub xlsx `종합` = `폴더미정리` + 이슈 없음 → `🟡 폴더 미정리`
- GitHub xlsx `종합` = `이슈있음` + 이슈 1건 → `🟡 경고`
- GitHub xlsx `종합` = `이슈있음` + 이슈 2건 이상 → `🔴 이슈 복수`
- GitHub xlsx `종합` = `실행오류` → `🟠 실행 오류`
- GitHub xlsx `종합` = `미제출` 또는 `미등록` → `⛔ 미제출`
- 폴더 비정상(미정리/비규격) + 코드 이슈 병존 시 → 이슈 건수로 판정 (`🟡 경고` 또는 `🔴 이슈 복수`)

### 3-3. 최종종합 (G열) — 판정 로직
```python
def final_status(lms, gh_status):
    lms_ok = lms in ("✅", "❌")       # .py 파일 존재 여부
    gh_ok  = gh_status != "⛔ 미제출"  # GitHub 제출 여부
    if not lms_ok and not gh_ok:
        return "미제출"
    elif lms == "✅" and gh_ok:
        return "제출"
    else:
        return "일부제출"
```

| 값 | 조건 | 색상 |
|----|------|------|
| 제출 | LMS `✅` **AND** GitHub `⛔ 미제출` **아님** | 초록 `D4EDDA` |
| 일부제출 | 그 외 (하나만 있거나, LMS `❌` 상태 포함) | 노랑 `FFF3CD` |
| 미제출 | LMS `—` AND GitHub `⛔ 미제출` | 회색 `E2E3E5` |

> ⚠ **중요**: LMS `❌`(파일 있으나 오류)인 경우 lms_ok=True로 처리되어 GitHub 상태에 따라 일부제출로 판정됩니다.

## 5. 로직이슈 작성 형식

### F열 — 줄글 서술
```
파일명.py: 이슈 설명; 파일명.py: 이슈 설명
```
- 이슈 없으면: `이상 없음`
- .py 파일이 아예 없고 GitHub도 이상 없으면: `이상 없음`
- LMS도 GitHub도 없으면: `—`
- 여러 이슈는 `;`으로 구분
- **[LMS]/[GitHub] 접두어 사용 금지** — LMS와 GitHub 이슈를 통합, 중복 제거 후 하나의 줄글로 서술

### H열~ — 코드 체크
F열에 서술한 이슈 중 해당 패턴이 있으면 그 열에 `✅` 표시, 없으면 빈칸.
**F열과 H~열은 항상 일치해야 함** (F열에 없는 이슈가 체크되면 안 됨).

## 10. LMS .py 파일 분석 방법

```bash
# 과제 폴더 내 모든 .py 파일 찾기
find "과제XX_폴더/" -name "*.py" | sort

# 각 파일 실행 테스트 (구문 오류 확인)
python3 -c "import ast; ast.parse(open('파일.py').read())"
```

**판정 기준:**
- `.py` 파일 있음 + `ast.parse()` 성공 → `✅`
- `.py` 파일 있음 + `ast.parse()` 실패 (SyntaxError) → `❌`
- `.py` 파일 없음 (온라인텍스트, .txt, .zip만 있음) → `—`
- 런타임 오류 (NameError, TypeError 등 실행 중 발생) → `❌`

**로직 이슈 확인 항목 (과제별 루브릭 기준으로):**
- 공식 오류 (변환식 계수, 연산 순서)
- 변수 미정의, 타입 오류
- 범위 외 입력 처리 (else/elif 누락)
- 출력 포맷 누락 (:.1f 등)
- 메뉴 구조 미준수
- 기타 논리 오류

## 11. LMS + GitHub 이슈 통합 규칙

| 상황 | F열 처리 |
|------|----------|
| LMS에만 이슈, GitHub 정상 | LMS 이슈만 서술 |
| GitHub에만 이슈, LMS 정상 | GitHub 이슈만 서술 |
| 양쪽에 동일한 이슈 | 이슈 하나만 서술 (중복 제거) |
| 양쪽에 서로 다른 이슈 | 세미콜론(;)으로 연결해 모두 서술 |
| LMS `—` + GitHub 이상 없음 | `이상 없음` |
| LMS `—` + GitHub `⛔ 미제출` | `—` |
| LMS 정상 + GitHub `⛔ 미제출` | LMS 이슈만 서술 (또는 `이상 없음`) |

**접두어([LMS], [GitHub]) 절대 사용하지 않음.**

## 13. TXT 파일 포함 내용

자동 생성되는 `과제XX_최종버전_기준.txt`에는 다음이 포함됩니다:
1. 과제 번호

3. 최종종합 판정 기준

   - 미제출 여부 (LMS·GitHub 각각 또는 둘 다)
   - 로직이슈 각 항목
   - 코드체크 플래그 항목

| K | 사분면\n조건/출력\n오류 | 조건 뒤바뀜, 좌표 미출력, 축 케이스 미처리 |
| L | 원 포맷\n반대 | 면적:.1f, 둘레:.2f (소수점 자리수 반대) |
| M | 원 계산\n오류 | pi 미사용, 둘레 공식 오류 |

### 과제05
| 열 | 헤더 | 체크 조건 |
|----|------|-----------|
| H | 범위외입력\n미처리 | 메뉴 1~4 외 입력 처리 없음 (else 없음) |
| I | 화씨→섭씨\n공식오류 | `(F-32)/1.8` 아닌 잘못된 공식 사용 |
| J | 섭씨→화씨\n공식오류 | `C*9/5+32` 아닌 잘못된 공식 사용 |
| K | 피트→cm\n공식오류 | `×30.48` 대신 다른 값 또는 역방향 연산 |
| L | cm→피트\n공식오류 | `÷30.48` 대신 `×2.54` 등 역방향 연산 |
| M | 소수점포맷\n누락 | `:.1f` 없이 출력 (`{:.1}` 오기재 포함) |
| N | 문자열비교\n혼용 | `input()` 반환값(str)을 정수와 직접 비교 |

## 20. 점수 계산 규칙

헤더 메모에 채점 기준 명시: `제출 5 | 오류 -0.5 | 우수 1`

| 항목 | 점수 |
|------|------|
| 기본 제출 | +5 |
| 미제출 | 0 |
| 항목별 오류 (문제당) | -0.5 |
| 우수 학생 (⭐) | +1 |
| 최고 가능 점수 | 6 |

### 점수 열 구조 (과제별 점수 열이 필요한 경우)

```
[기본점수] | 문제1오류 | 문제2오류 | 문제3오류 | 파일저장미구현 | 우수학생 | 최종
```

- 정상이면 빈칸, 오류/미구현이면 `-0.5`
- 우수학생이면 `1`, 아니면 빈칸
- 최종 = 기본점수 + 감점 합산 + 우수점수

### 최종종합 값 (점수 열 없는 현행 형식)

| 값 | 사용 기준 |
|----|-----------|
| `이상없음 ⭐` | 로직 완벽, 파일저장·예외처리 등 추가 구현까지 완성도 높음 |
| `이상없음` | 로직 정상, 특별히 우수하지는 않음 |
| `경미한 이슈` | 오류는 아니지만 개선 필요 (minor 수준, 감점 없음) |
| `이슈` | 특정 항목 1개 오류 또는 미구현 |
| `이슈복수` | 오류/미구현 2개 이상 |
| `미제출` | LMS + GitHub 모두 미제출 |
| `미구현` | 제출은 했으나 핵심 기능이 구현되지 않음 |
| `GitHub미제출` | LMS는 제출했으나 GitHub에 없음 |
| `LMS 미제출` | GitHub는 있으나 LMS에 없음 |

> **참고:** `build_report.py` 스크립트는 `제출 / 일부제출 / 미제출` 3단계 판정을 사용한다. 위 값은 수동 작성 시 또는 스타일 가이드 기반 리포트 작성 시 사용한다.
